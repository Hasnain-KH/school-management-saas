# Environment configuration

This document lists the environment variables read by SchoolFlow source and its test tooling. The actual `backend/.env` is private and is not required to be read or committed. Keep credentials in an ignored local `.env` file or the deployment platform's secret manager.

## Backend runtime

| Variable | Required? | Local development | Vercel production | Default / behavior | Owner and use | External credential? |
|---|---|---|---|---|---|---|
| `MONGO_URI` | Yes | Yes | Yes | No default; startup/config validation fails without it. | Backend: `backend/src/config/env.js`, `backend/src/config/db.js`, and `backend/scripts/create-indexes.js`; MongoDB connection. | Yes: MongoDB connection URI and database access. Use a replica set for transactions. |
| `JWT_ACCESS_SECRET` | Yes | Yes | Yes | No default; must be at least 32 characters. | Backend: `backend/src/config/env.js`; access-token signing and verification. | Secret value; generate and store privately. |
| `JWT_REFRESH_SECRET` | Yes | Yes | Yes | No default; must be at least 32 characters and differ from the access secret. | Backend: `backend/src/config/env.js`; refresh-token signing and verification. | Secret value; generate and store privately. |
| `RATE_LIMIT_REDIS_URL` | No for local development; required in production | Optional; without it local development and tests use the process-local limiter. | Yes; missing configuration fails startup/request setup, and provider errors return `503` rather than falling back to memory. | No default. Supports Redis-protocol `redis://` or `rediss://` URLs; counters use atomic increments and separate API/authentication key prefixes. | Backend: `backend/src/services/rate-limit-store.js` and `backend/src/middleware/rate-limit.middleware.js`. | Yes: a Redis-compatible service connection URL, stored only in backend secrets. |
| `CORS_ORIGINS` | No for default local origins; required in production | Optional. If unset, allows `http://localhost:3000` and `http://localhost:5173`. Set it when the frontend uses a different origin. | Yes. Production configuration rejects an empty allowlist. | No production default. Comma-separated exact origins; no wildcard is implied. | Backend: `backend/src/config/env.js` and `backend/src/app.js`; CORS allowlist. | No. Supply the actual frontend origin(s), including scheme and host. |
| `NODE_ENV` | Yes for direct server/config startup; `npm run dev` sets `development` when unset, and backend tests set `test`. | Accepted values are exactly `development`, `test`, and `production`; other or missing values fail configuration validation. | Set explicitly to `production` for Vercel. Missing or invalid values fail closed before serving requests; production mode disables Mongoose automatic index creation and requires configured CORS and Redis. | No configuration default. The `dev` script supplies `development` only when unset. | Backend: `backend/src/config/env.js`, `backend/scripts/start-dev.js`, and `backend/src/config/db.js`. | No. |
| `PORT` | No | Optional; defaults to `5000` for the local Express server. | Do not configure for Vercel unless the platform's Node runtime specifically requires it; the serverless function does not call `listen()`. | `5000`; must be an integer from 1 to 65535. | Backend: `backend/src/config/env.js` and `backend/src/server.js`. | No. |
| `TRUST_PROXY_HOPS` | No in local development | Defaults to `0`. | Configure to the trusted proxy hop count for the Vercel request path; deployment docs currently recommend `1`. | `0`; must be a non-negative integer. Controls Express `trust proxy`. | Backend: `backend/src/config/env.js`, `backend/src/server.js`, and `backend/src/serverless-handler.js`. | No. |
| `ACCESS_TOKEN_TTL` | No | Optional override. | Optional override. | `15m`. Duration syntax is a positive integer followed by `s`, `m`, `h`, or `d`, maximum 365 days. | Backend: `backend/src/config/env.js`; access-token lifetime. | No. |
| `REFRESH_TOKEN_TTL` | No | Optional override. | Optional override. | `7d`, maximum 365 days. | Backend: `backend/src/config/env.js`; refresh-token lifetime and persisted-session expiry. | No. |

`MONGO_URI` should point to a database dedicated to the environment. Transactional workflows need a MongoDB replica set. Production index creation is disabled by design; apply reviewed indexes with the documented migration process, not by turning on automatic index creation.

## Frontend build

| Variable | Required? | Local development | Vercel production | Default / behavior | Owner and use | External credential? |
|---|---|---|---|---|---|---|
| `VITE_API_URL` | No | Defaults to `http://localhost:5000/api/v1`. Override only when the API is at another origin/path. | Leave unset for the configured same-origin deployment; default is `/api/v1`. For a split API deployment, set it to the API origin plus `/api/v1`. | Environment-specific fallback as described. Trailing slash is removed. | Frontend: `frontend/src/api/client.js`, substituted at Vite build time. | No. It is an API URL, not a secret. Do not place credentials or private keys in `VITE_*` variables; they are shipped to browsers. |

There are no required frontend environment variables for the default local or same-origin Vercel setup. `frontend/.env.example` contains only the optional `VITE_API_URL` override and deliberately leaves it blank.

## Test/tooling-only variables

| Variable | Required? | Use and default | Notes |
|---|---|---|---|
| `MONGO_TEST_URI` | Optional; required only to execute the real MongoDB integration test instead of skipping it. | No default. The integration test requires a URI database name beginning with `schoolflow_test` and uses two uniquely named collections inside only that explicitly named database. | Backend test only: `backend/test/mongo.integration.test.js`. Use credentials scoped to an isolated test-only replica set/database; never point this at production. |
| `MONGO_TEST_ALLOW_REMOTE` | No for local loopback MongoDB; required as an explicit safety acknowledgement for non-loopback hosts. | Defaults to unset. Set to the literal `true` only after independently confirming `MONGO_TEST_URI` points to a dedicated non-production test cluster. | Not a production setting; do not configure in Vercel. | No default. The test refuses remote hosts without this opt-in and still requires the `schoolflow_test` database prefix. | Backend integration-test guard: `backend/test/mongo.integration.test.js`. | No credential; this is only an explicit remote-test safety acknowledgement. |
| `SCHOOLFLOW_REDIS_INTEGRATION` | Optional; required to run the real Redis smoke test. | Must be the literal `true`; otherwise the test skips. | Do not configure in production. | No default. | Backend test only: `backend/test/redis.integration.test.js`. | No. |
| `RATE_LIMIT_REDIS_TEST_URL` | Required only when explicitly running the Redis smoke test. | No default. Must be a dedicated non-production Redis test database; remote endpoints must use TLS. Must not share the production Redis host and port. | Do not configure in production. | Used only by the opt-in Redis smoke test. | Backend test only: `backend/test/redis.integration.test.js`. | Yes: test-only Redis connection URL. |
| `CI` | Optional. | Playwright uses it to forbid focused tests and enable one retry; absent means local test behavior. | Frontend test tooling only: `frontend/playwright.config.js`. |
| `DOTENV_CONFIG_PATH` | Optional tooling override, not an application setting. | `dotenv/config` otherwise follows dotenv's normal `.env` lookup. | Can point tests at a nonexistent file to avoid loading a developer `.env`; do not set it as a production runtime variable. |

Backend unit/request tests set their own test values inside test files, including a non-routable local Mongo URI for mocked paths. They do not require a live database. `MONGO_TEST_URI` is separate and is the only URI used by the opt-in integration test. To run it safely, provision a dedicated non-production MongoDB replica set and database with a name beginning `schoolflow_test`; provide a test-only identity with permissions limited to that database. Set `MONGO_TEST_URI` only in the private shell or secret manager used to run `npm test --workspace backend`. For a remote cluster, additionally set `MONGO_TEST_ALLOW_REMOTE=true` only after verifying it is isolated. The test uses only the database named in the URI, creates two randomized test collections there, and drops only those exact collections in `finally`; it never drops the database or reads `MONGO_URI`/`.env`. The integration case skips when `MONGO_TEST_URI` is absent and refuses to run with `NODE_ENV=production`.

The Redis smoke test is separate from the ordinary backend suite. Provision a dedicated non-production Redis database and test credentials before opting in; never use production Redis. Supply `RATE_LIMIT_REDIS_TEST_URL` through a private shell or secret manager and set `SCHOOLFLOW_REDIS_INTEGRATION` to the literal `true`, then run `npm run test:redis:integration` from the backend directory. Remote Redis connections must use TLS. The test uses the real API and auth limiter configuration, a unique `schoolflow:redis-integration:<run-id>:` key prefix, and only scans/deletes keys under that prefix. Ensure the test credential can run the store's script commands and `SCAN`/`DEL` only within the dedicated test database. The test skips without the opt-in flag and never reads `.env` or falls back to `RATE_LIMIT_REDIS_URL`.

## Vercel configuration and external providers

`vercel.json` does not declare environment variables. It configures the frontend build/output, serverless API function, SPA routing, and same-origin Content-Security-Policy headers. Configure secrets in Vercel's encrypted environment settings, not in `vercel.json`. The `VITE_API_URL` value is public build-time configuration; the backend URI, JWT secrets, and Redis URL are server-only. Production cookie authentication requires HTTPS; the default single-project Vercel deployment is same-origin. A split API deployment also requires adding its exact API origin to the Vercel `connect-src` policy, using a same-site frontend/API hostname arrangement, and listing exact frontend origins in `CORS_ORIGINS`.

No email, payment, document-storage, or monitoring provider credentials are currently read from environment variables. Provider interfaces explicitly remain unavailable until real adapters are implemented and configured. Do not add credentials for these services to the example files until corresponding implementations exist.
